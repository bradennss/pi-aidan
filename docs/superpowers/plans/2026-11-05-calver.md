# CalVer project versioning implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Default new Aidan projects to `YYYY.MDD.R` CalVer while preserving existing versioning.

**Architecture:** Add a concise system policy and actionable project-setup guidance. Document the policy and verify examples and prompt integration without adding wording assertions or release automation.

**Tech Stack:** Markdown prompts and skills, TypeScript, Vitest, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-05-calver-design.md`

## Global constraints

- Use `YYYY.MDD.R`, with `MDD = month × 100 + day`, the UTC release date, and `R` starting at `1` each day.
- Never reuse a published version. Numeric segments have no leading zeros.
- Preserve existing project versioning unless migration is requested; explicit user directions take precedence.
- Document breaking changes in release notes; CalVer does not promise API compatibility.
- No package-version change, release automation, new dependencies, or implicit migration.
- No commits or pushes without user authorization.

## Review focus

- January single-digit days: January 5 becomes `105`, not `0105` or `15`.
- Same-day releases: increment the published counter rather than reset or reuse it.
- UTC date rollover: reset the counter to `1` on the new UTC date.
- Established SemVer project: retain its scheme without a migration request.
- New project guidance: explain the version contract rather than leaving the initializer's placeholder version unexplained.
